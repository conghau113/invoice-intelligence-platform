# T0.9 — Ghi chú cổng hiểu (Context engineering cho agent)

## 1. CLAUDE.md, skill và hook khác nhau thế nào

**Câu hỏi:** CLAUDE.md, skill và hook là gì, mỗi thứ giải quyết vấn đề gì, thiếu một trong ba thì dự án này hỏng gì?

**Trả lời:**
- **CLAUDE.md**: ngữ cảnh luôn nạp mỗi phiên. Chứa luật nền (i18n, tenant, PII, chi phí 0đ), bản đồ repo và lệnh chạy. Agent khỏi cần được nhắc lại trong mỗi prompt. Là luật "mềm".
- **Skill**: quy trình theo việc (`/task`, `/gate`, `/adr`), chỉ nạp thân skill khi được gọi. Chuẩn hóa vòng lặp: đọc spec, đối chiếu, lập kế hoạch, chờ duyệt, dán bằng chứng, cập nhật sổ.
- **Hook**: code chạy trước khi công cụ thực thi (`PreToolUse`). Mã thoát 2 là chặn. Là chốt cứng, agent quên CLAUDE.md vẫn bị chặn.
- Thiếu CLAUDE.md: agent lệch phạm vi, sai lệnh, trái ADR. Thiếu skill: mất quy trình và bằng chứng, khó review. Thiếu hook: lệnh "đừng đọc file env" chỉ còn là lời nhắc.

**Lưu ý:**
- Chỉ phần mô tả skill nằm sẵn trong ngữ cảnh. Thân skill chỉ vào khi gọi, nên skill dài không tốn quota như CLAUDE.md dài (CLAUDE.md nên dưới 200 dòng).
- `/task` đặt `disable-model-invocation: true`: chỉ người gõ được, agent không tự khởi động task.
- Hook dựa trên regex nên không tuyệt đối; cần thêm lớp `permissions.deny`.

## 2. Luồng một lời gọi công cụ đi qua hook

**Câu hỏi:** Khi agent định đọc file bí mật của app api, chuyện gì xảy ra từ đầu đến cuối? Đổi sang file `.example` thì khác gì?

**Trả lời:**
1. Agent chỉ *xin* gọi `Read`; chưa có nội dung nào được đọc.
2. Claude Code chạy hook `PreToolUse` theo `matcher` trong `settings.json`.
3. `guard.mjs` đọc JSON từ stdin, `decide` kiểm đường dẫn bằng `isSecretPath`. Khớp thì ghi lý do ra stderr và thoát mã 2.
4. Công cụ không chạy; agent nhận thông báo chặn và phải giải thích hoặc dùng file mẫu.
5. Với file `.example`, `isSecretPath` trả false, hook thoát mã 0, `Read` chạy. Cho phép có chủ đích để agent vẫn mô tả được biến môi trường mà không chạm giá trị thật.

**Lưu ý:**
- Mã thoát có nghĩa riêng: 2 chặn và đưa stderr cho agent, 0 cho qua, mã khác chỉ là lỗi không chặn.
- `guard.mjs` fail-open khi JSON đầu vào hỏng (thoát 0). Chủ ý để hook lỗi không làm tê liệt phiên, nhưng là một kẽ hở.
- `decide` kiểm cả lệnh Bash: chuỗi tên file env nằm trong lệnh là bị chặn, kể cả khi chỉ nằm trong heredoc sửa file khác.

## 3. Đánh đổi của cưỡng chế bằng hook

**Câu hỏi:** Cưỡng chế bằng code đổi lấy gì so với chỉ viết trong CLAUDE.md? Hook thất bại theo những cách nào? Vì sao dùng cả hook lẫn `deny`?

**Trả lời:**
- Đổi lấy: an toàn cưỡng chế đổi bằng ma sát, chặn nhầm và chi phí bảo trì regex. Luật mềm rẻ nhưng không đủ cho bí mật; luật cứng không miễn phí.
- Ba kiểu hỏng: **chặn nhầm** (lệnh vô hại chứa tên file env bị dừng; cách tránh là dùng Edit/Write hoặc tách lệnh); **bỏ sót** (đường dẫn hoặc cách lách regex không bắt được, secret vào ngữ cảnh); **hỏng im lặng** (hook lỗi, bị gỡ khỏi settings, hoặc test không chạy trong CI nên không ai biết).
- Dùng cả hai lớp vì chúng bổ sung nhau: `deny` là lớp cấu hình của Claude Code, hook có logic tinh hơn (cho `.example`, chặn lệnh nguy hiểm).

**Lưu ý:**
- `deny` trong repo này chỉ phủ `Read`/`Edit`/`Write` file env. Lệnh Bash như `cat` file env chỉ do hook chặn, nên hai lớp không giống hệt nhau.
- `.gitignore` bảo vệ remote nhưng không ngăn agent đọc file cục bộ. Secret manager mạnh hơn nhưng ngoài phạm vi M0.
- Test của hook (`guard.test.mjs`) chưa nằm trong `check:full` hay CI; xem dòng Phát sinh T0.9 trong `TASKS.md`. Cổng không thể fail là cổng vô dụng.
