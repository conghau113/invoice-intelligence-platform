## Cách tự chạy lại
```bash
pnpm infra:up                      # realm mới cần `docker compose down -v` một lần
# apps/web/.env.local: NEXTAUTH_URL, NEXTAUTH_SECRET (>=32 ký tự), KEYCLOAK_ISSUER, KEYCLOAK_CLIENT_ID, KEYCLOAK_CLIENT_SECRET
pnpm --filter web dev
pnpm --filter web test             # 56 test, không cần Keycloak
```
Bằng tay: mở http://localhost:3000/dashboard → về /login → đăng nhập `admin@acme.example` / `demo-dev-only` (2 bước: username rồi mật khẩu) → /dashboard hiện tenant `acme` → "Sign out" → về /login; đăng nhập lại phải hỏi mật khẩu. Chọn tenant: `/login?tenant=globex`. Refresh: hạ `accessTokenLifespan` realm local xuống 90s, đợi >30s rồi tải lại /dashboard.

Kết quả đã chạy với Keycloak thật (script ngoài repo): signed-out → 307 /login; login → /dashboard 200, cookie HttpOnly + SameSite=Lax, không có JWT trong HTML; `consultant` + `?tenant=globex` → tenant `globex`; chờ 45s với lifespan 90s → 5 request song song cùng cookie cũ đều 200, cookie được cấp lại, và một request đến muộn mang cookie cũ sau khi refresh xong cũng 200; logout cross-origin → 403, logout hợp lệ → 303 end_session, sau đó Keycloak hiện lại form đăng nhập (SSO đã hết). Drill: đặt `REUSE_WINDOW_MS = 0` → 2 test đỏ (song song và request đến muộn).

## Phương án đã loại
- Tự viết OIDC bằng `openid-client`/`jose` + cookie tự quản: PKCE/state/mã hoá cookie là phần dễ sai nhất; ADR 0006 đã chọn Auth.js.
- `next-auth` v5 beta: ADR yêu cầu "stable major"; v5 vẫn là beta.
- Refresh trong callback `jwt` (bản đầu có làm vậy, đã bỏ sau review): Server Component không ghi được cookie, nên token vừa xoay không được lưu, lần sau dùng refresh token đã bị thu hồi → người dùng bị văng. Vì vậy refresh đặt ở `proxy.ts`, nơi ghi được cookie.

## Khái niệm học được
- **BFF**: trình duyệt chỉ giữ cookie mã hoá, token ở server. `options.ts` (session callback không trả token), `proxy.ts:29` (đọc cookie phía server). Trong task này: JS trên trang không bao giờ thấy access/refresh token.
- **Cookie httpOnly/SameSite**: `proxy.ts` (`res.cookies.set`). httpOnly chặn XSS đọc token; SameSite=Lax giảm CSRF.
- **Authorization Code + PKCE**: `options.ts:38` (`checks: ['pkce','state']`); client `web` trong realm bắt S256.
- **Refresh token rotation**: `refresh.ts` lưu refresh token mới; realm `revokeRefreshToken`. Token bị Keycloak từ chối (`rejected`) → đăng xuất (`proxy.ts:45`).
- **Single-flight + cửa sổ tái dùng**: `refresh.ts:6,34,74`.
- **Proxy (ex-middleware) kiểm tra lạc quan**: `guard.ts:6`, `proxy.ts:29`. Chỉ đọc cookie; API vẫn là nơi cưỡng chế.
- **end_session**: `logout.ts:1` (id_token_hint, post_logout_redirect_uri).

## Sau code-review
Reviewer tìm ra (đã sửa): race khi request đến muộn mang refresh token cũ (H1); Keycloak lỗi tạm thời bị coi là đăng xuất (M1); không timeout khi gọi Keycloak (M2); `authEnv()` chạy trước kiểm tra route công khai nên `/api/health` cũng 500 khi thiếu env (M3); callback `jwt` còn đường refresh không lưu được cookie (M4); thiếu test nhiều mảnh cookie, https, route logout, lọc `callbackUrl`/`tenant` (M5, L1). Chưa sửa, ghi Phát sinh: `/api/auth/signout` mặc định của next-auth chỉ xoá cookie local, không gọi end_session (L3); redirect của proxy mất query string và trả 307 cho cả request không phải GET (L4); dùng chung `KEYCLOAK_ISSUER` cho gọi server-to-server và redirect trình duyệt (L5).
