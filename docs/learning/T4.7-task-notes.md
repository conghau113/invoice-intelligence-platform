## Phương án đã loại

- **Caddy `/api` → API (đúng như spec ghi).** Web dùng chính `/api/*` cho BFF và next-auth, nên làm vậy sẽ hỏng đăng nhập. Mặt khác trình duyệt không có token (ADR 0006), nên mở API ra internet không có lợi gì mà còn tăng bề mặt tấn công. Đã chọn: chỉ web và hai path đăng nhập của Keycloak là public.
- **Build image trên laptop rồi push GHCR.** Cách này cần PAT, công khai image, và trùng việc của T7.5. Build native trên VM arm64 thì không cần registry. Khả năng build arm64 đã được kiểm trước bằng QEMU.
- **Seed dữ liệu demo từ đáp án (`expected.json`).** Như vậy trang sẽ hiện độ chính xác 100%, tức là số giả. Đã chọn: snapshot của tài liệu chạy pipeline thật trên máy dev.
- **Container "ballast" giữ RAM** để vượt ngưỡng idle. Cách này không có ý nghĩa vận hành nào. Đã chọn: heap JVM cố định và chạm trước, là cấu hình production thường gặp.
- **`output: 'standalone'` luôn bật.** Next báo `next start` (dùng trong e2e CI) không hỗ trợ tổ hợp này, nên chỉ bật khi build image.

## Rủi ro

- **Tài khoản demo dùng chung có thể bị chiếm (đã xảy ra trong diễn tập, đã sửa).** Gỡ `manage-account` là chưa đủ: chỉ cần URL đăng nhập có `kc_action=UPDATE_PASSWORD` là Keycloak hiện form đổi mật khẩu, đổi profile, bật TOTP. Bất kỳ khách nào cũng có thể khoá cả demo. Đã sửa bằng cách tắt mọi required action thay đổi tài khoản (`build-realm.mjs:82`). Có test ở `scripts/prod-infra.test.mjs`, và đã kiểm lại bằng trình duyệt: không còn form nào.
- **RAM dưới ngưỡng idle của Oracle.** Đo thật cả stack chỉ ~1,1 GB (8,9%), không phải 25% như tài liệu cũ ước tính. Sau khi đặt heap Keycloak cố định 2 GB chạm trước (`compose.prod.yaml:249`), container lên 2.816 MiB (22,9%), chưa tính hệ điều hành. Vẫn còn mở: con số đo trên VM thật (ghi vào learning-log), và cảnh báo hằng ngày ở T7.5.
- **Seed hỏng với owner không phải superuser (đã sửa).** Ở dev không lộ vì owner dev là superuser, và test tích hợp cũng seed bằng superuser (Phát sinh cho T7.5).
- **Realm chỉ import ở lần đầu.** Muốn đổi realm production phải dựng lại DB Keycloak (Phát sinh T7.5).
- **Build web cần mạng để tải Google Fonts** (Phát sinh T3.9/T4.1 còn mở). VM có mạng nên vẫn build được.
- **Diễn tập chạy trên amd64**, còn VM là arm64. Cả 3 image đã build được cho `linux/arm64` bằng QEMU (api 893 s, web 1.192 s) và khởi động được dưới giả lập: API dừng vì thiếu biến môi trường chứ không thiếu module, web có `apps/web/server.js`, AI import xong trên `aarch64`. Stack đầy đủ thì phải chạy trên VM mới chắc.
- **Overrides phụ thuộc.** Phải gỡ khi parent tự nâng. Upload qua multer 2.5.0 đã chạy trong `test:int`.
- **E2E Playwright chưa chạy trên máy** vì cần file env dev. CI sẽ chạy. `next start` với build mặc định (không standalone) đã kiểm tay.
- **Chưa có demo public.** T4.8 phải dùng GIF/ảnh chụp từ bản local; link public tới T7.5. Đã cân nhắc các nền tảng thay thế 0đ (GCP, AWS, Render, Koyeb, Hugging Face, Cloud Run + Neon, tự host + Tailscale Funnel), không cái nào vừa 0đ vừa chạy y nguyên mà không cần máy bật 24/7 (chi tiết ở dòng Phát sinh).
- Đã mirror sang Phát sinh: route Socket.IO cho M6, `qa:ask` cho T5.5, admin tạm của Keycloak, jest đôi khi in cảnh báo worker không thoát.

## Sau code review (2026-11-10)

Reviewer báo 0 lỗi Cao, 2 lỗi Vừa, 5 lỗi Thấp. Đã kiểm lại trên bản diễn tập cài mới từ đầu.

- **Vừa, đã sửa: realm `master` lộ ra internet.** Caddy cho qua mọi `/auth/realms/*`, nên token endpoint của realm `master` công khai, ai cũng có thể đoán mật khẩu admin tạm. Giờ chỉ cho qua `/auth/realms/invoice/*` và `/auth/resources/*` (`Caddyfile`). Đo lại: mọi path của `master` trả 404, kể cả POST token; realm `invoice` vẫn đăng nhập được.
- **Vừa, đã sửa: import ghi file trước transaction.** Chèn dữ liệu lỗi thì file bị bỏ lại. Giờ lỗi sẽ rollback rồi xoá các file vừa ghi (`demo-snapshot.mjs`). Đo bằng một snapshot cố ý hỏng (extraction trỏ tới tài liệu không tồn tại): lỗi FK, còn 0 file và 0 tài liệu. Sau đó import bản đúng được 70 tài liệu, import lần hai bị từ chối (exit 1).
- **Thấp, không lỗi: quyền volume `/data` khi cài mới.** Container api mount volume ở chế độ `:ro` đầu tiên, và volume vẫn thuộc `node:node` (đã kiểm bằng `ls -ld /data`).
- **Thấp, có bằng chứng thay test: luồng SQL của import.** Chưa có test tự động; bằng chứng là 3 lần chạy thật ở trên, trên Postgres production của bản diễn tập. Test tự động cho `importSnapshot` cần Postgres, có thể làm cùng T7.5.
- **Thấp, chuyển T7.5: image chưa ghim digest** (Phát sinh).
- **Thấp, đã ghi chú: thư mục `public/` của web.** Hiện chưa có. Dockerfile ghi rõ cách chép thêm nếu sau này cần.
- **Thấp, chấp nhận: JSON body được parse trước guard.** API không public, giới hạn body vẫn áp dụng. Rate limit để T6.1.
