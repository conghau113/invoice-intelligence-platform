# T0.5 — Ghi chú cổng hiểu (packages/contracts: Zod → JSON Schema → pydantic)

## 1. Luồng chạy

**Câu hỏi:** Thêm field `note` (chuỗi bắt buộc) vào `InvoiceDraftSchema` và muốn Python dùng được. Kể từ đầu đến cuối: sửa file nào, chạy lệnh nào, mỗi lệnh đọc và tạo file nào, `generated.py` được dùng ở đâu?

**Trả lời:** Sửa `packages/contracts/src/invoice.ts` và fixture hợp lệ (`fixtures/invoice.valid.json`). Chạy `pnpm --filter contracts build`: `tsc` biên dịch ra `dist/`, rồi `node dist/export-json-schema.js` gọi `z.toJSONSchema` và ghi `dist/invoice-draft.schema.json`. Chạy `pnpm --filter contracts generate:python`: `scripts/generate-python.sh` đọc JSON Schema đó, gọi `uv run datamodel-codegen` trong `apps/ai` và ghi đè `apps/ai/app/schemas/generated.py` (class `InvoiceDraft`). Hiện chỉ `apps/ai/tests/test_contract.py` import file này; chưa có router hay service nào dùng.

**Lưu ý:**

- Thứ tự `build` rồi `generate:python` là bắt buộc: `generate:python` không tự build, quên `build` thì sinh lại từ JSON Schema cũ. `check:drift` tự build nên bắt được lỗi này.
- Các test dựng từ fixture hợp lệ (`fractional_money`, `numeric_string_money`, `unknown_key`) vẫn fail khi fixture thiếu `note`, nhưng vì sai lý do. Chỉ test "fixture hợp lệ phải pass" báo đúng chỗ.
- Commit cả `src/invoice.ts` lẫn `generated.py` cùng nhau; `dist/` nằm trong `.gitignore`.

## 2. Vì sao chọn cách này

**Câu hỏi:** Vì sao Zod là nguồn rồi sinh Python, thay vì viết hai bộ model bằng tay? Phương án khác và đánh đổi? Nhược điểm của cách hiện tại?

**Trả lời:** Hóa đơn dùng ở form web, API, worker và làm schema output của LLM. Viết tay hai bộ thì thêm field ở một nơi mà quên nơi kia, hai phía hết cùng một hợp đồng: `forbid` thì từ chối field hợp lệ, `ignore` thì field biến mất trước khi lưu. Phương án khác: không sinh model, Python validate trực tiếp bằng `jsonschema`; bỏ bước sinh nhưng mất class có type (IDE không gợi ý, lỗi tên field chỉ lộ lúc chạy) trong khi pipeline cần model pydantic. Nhược điểm hiện tại: JSON Schema không mang hết nghĩa của Zod nên pydantic có thể lỏng hơn; `refine` và `transform` không sang được nên business rule để ngoài schema; có thêm một bước sinh phải bảo trì và output phụ thuộc phiên bản công cụ.

**Lưu ý:**

- Thư viện `jsonschema` mặc định không kiểm `format: "date"` nếu không bật `format_checker`, nên phương án thay thế còn dễ lỏng hơn.
- ADR 0004 còn một phương án nữa: OpenAPI-first, bị loại vì đi từ API chứ không từ schema dùng chung; chỉ thêm khi cần API công khai cho bên thứ ba.
- Ở đây chọn sinh model có type vì AI_PIPELINE §4 yêu cầu validate bằng pydantic sinh từ JSON Schema.

## 3. Hỏng ở đâu

**Câu hỏi:** Ba tình huống: (1) sửa Zod nhưng quên `generate:python`; (2) LLM trả key lạ `"surprise": 1`; (3) LLM trả `"issueDate": "2026-03-15T00:00:00"`. Lỗi lộ ở đâu, test nào bắt?

**Trả lời:** (1) `generated.py` cũ, mọi test xanh nếu fixture không chạm giới hạn mới; chỉ `pnpm --filter contracts check:drift` bắt (build, sinh bản tạm, `diff`, exit 1 kèm `DRIFT`), và lệnh này chưa có trong CI (T0.7). (2) Lộ lúc validate: Zod dùng `z.strictObject`, pydantic `extra="forbid"`; bắt bởi `rejects unknown keys` trong `test/contract.spec.ts` và `test_unknown_key_fails`. (3) Zod `z.iso.date()` từ chối, pydantic `date` nhận (và cũng nhận số nguyên) vì bỏ qua `pattern`; chưa có test nào phủ, ghi ở "Phát sinh" cho T2.7.

**Lưu ý:**

- Có tầng thứ hai: Python validate output LLM trước, rồi API/worker validate lại bằng Zod. Ngày sai vẫn bị Zod chặn ở tầng sau nên không tới DB, nhưng lỗi lộ muộn và sai chỗ.
- Contract test chỉ phủ giá trị có trong fixture. Muốn bắt kiểu `.max(20)` cần fixture sát biên (đúng 20 và 21 ký tự); làm ở T2.7.
- Ban đầu agent dùng `z.object` (bỏ key lạ), lệch với `extra="forbid"` bên Python; reviewer phát hiện, đã đổi sang `z.strictObject`.

## 4. Câu hỏi cổng hiểu

**Câu hỏi:** Nguồn sự thật của schema nằm ở đâu? Nếu Python cần field mới thì quy trình thế nào? (Tình huống: đồng đội muốn thêm `ocrConfidence`, chỉ dùng để debug ở service AI, thẳng vào `generated.py`.)

**Trả lời:** Nguồn sự thật là `InvoiceDraftSchema` trong `packages/contracts/src/invoice.ts`; `generated.py` chỉ là bản sinh ra. Field mới dùng chung: sửa Zod, `build`, `generate:python`, sửa fixture, commit cả hai. Không sửa tay `generated.py`: lần sinh sau ghi đè và xóa field, và `check:drift` thoát mã 1. Nếu field bắt buộc thì `test_valid_fixture_passes` cũng đổ. Field chỉ dành cho Python thì đặt ở model viết tay cạnh chỗ dùng (ví dụ `apps/ai/app/schemas/ocr_debug.py`) bọc `InvoiceDraft`, không sửa nó.

**Lưu ý:**

- Trước khi tách ra khỏi hợp đồng, hỏi xem field có cần tới web, API hoặc LLM không. Nếu có thì phải vào Zod. Ở đây độ tin cậy theo field có chỗ riêng là `fieldMeta` (AI_PIPELINE §3), thuộc T2.7.
- Model bọc cũng nên `extra="forbid"` để không mở lại lỗ key lạ.
