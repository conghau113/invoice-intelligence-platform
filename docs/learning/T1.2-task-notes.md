# T1.2 — Ghi chú task: API xác thực JWT qua JWKS

## Đã làm

- `apps/api/src/modules/auth/` (mới): `JwtAuthGuard` (global, deny-by-default), `@Public()`, `@CurrentUser()`, `@CurrentTenant()`, `JoseTokenVerifier`, `mapClaimsToUser`, `tenant-directory`, `GET /auth/me`.
- `config/env.schema.ts`: `OIDC_ISSUER_URL` (bắt buộc), `OIDC_JWKS_URL`, `OIDC_AUDIENCE`; `apps/api/.env.example` cập nhật.
- `health.controller.ts`: `@Public()`.
- `infra/keycloak/realm-invoice.json`: thêm scope `basic` cho client `web` và `dev-cli` (sửa lỗi T1.1: thiếu `sub`).
- Phụ thuộc mới: `jose@^5` (MIT, trong allow-list `docs/LEGAL.md`; ghim v5 vì API là CommonJS).

## Rủi ro lớn nhất

- Tenant lấy từ claim `organization`, nên mọi thứ dựa vào cấu hình mapper của Keycloak. Token nhiều tenant bị từ chối thay vì đoán tenant.
- Test dùng token tự ký, có thể lệch so với token thật (đã lệch một lần: thiếu `sub`). Vì vậy đã chạy thêm kiểm tra với Keycloak thật.
- `tenant-directory.ts` là bảng tĩnh, phải thay ở T1.3.

## Phương án đã loại

`passport-jwt` + `jwks-rsa`: thêm 2 phụ thuộc, lớp callback của passport che mất các kiểm tra iss/aud/alg cần giải thích được; `jose` một mình đã có cache JWKS và tự tải lại khi gặp `kid` lạ.

## Khái niệm → vị trí

- Chốt `alg` chống `none`/HS256 confusion: `modules/auth/infra/jose-token-verifier.ts` (`algorithms: ['RS256']`).
- Cache JWKS + xoay khóa: cùng file (`createRemoteJWKSet`, `cooldownDuration`); test `key rotation` trong `jwt-auth.guard.spec.ts`.
- Deny-by-default: `APP_GUARD` trong `auth.module.ts`, bỏ qua bằng `@Public()` (`http/public.decorator.ts`).
- Tenant chỉ từ token: `application/claims-mapper.ts`; test header giả `X-Tenant-Id` bị bỏ qua.

## Cách tự chạy lại

```bash
pnpm --filter api test
pnpm infra:up
OIDC_ISSUER_URL=http://localhost:8080/realms/invoice NODE_ENV=development pnpm --filter api start:dev
T=$(curl -s -d grant_type=password -d client_id=dev-cli -d username=accountant@acme.example \
  -d password=demo-dev-only -d scope=openid \
  http://localhost:8080/realms/invoice/protocol/openid-connect/token | node -pe "JSON.parse(require('fs').readFileSync(0)).access_token")
curl -i localhost:3001/auth/me                              # 401
curl -i -H "Authorization: Bearer $T" localhost:3001/auth/me # 200 userId/tenantId/roles
```

Kết quả đã chạy 2026-10-17: không token 401; token sửa 1 ký tự 401; token acme 200 (`tenantId ...0a1`, roles `["accountant"]`); consultant với `organization:*` 403; với `organization:globex` 200 (`...0a2`); `/health` 200 không cần token. Realm JSON chỉ được kiểm trên Keycloak đang chạy (thêm `basic` qua Admin API); chưa chạy lại `down -v`.
