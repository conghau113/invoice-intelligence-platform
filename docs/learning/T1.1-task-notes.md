## Cách tự chạy lại

```bash
docker compose down -v && docker compose up -d --wait   # xóa volume → realm import lại từ đầu
docker compose logs keycloak | grep -E "Realm 'invoice' imported"

# Lấy token user acme (client dev-cli), xem payload
curl -s -X POST http://localhost:8080/realms/invoice/protocol/openid-connect/token \
  -d grant_type=password -d client_id=dev-cli -d username=accountant@acme.example \
  -d password=demo-dev-only -d scope=openid \
  | node -e "process.stdin.on('data',d=>console.log(JSON.parse(Buffer.from(JSON.parse(d).access_token.split('.')[1],'base64url'))))"
```

Kết quả đã chạy ngày 2026-10-17:
- Log: `Realm 'invoice' imported`, `Import finished successfully`.
- `accountant@acme.example`: `organization: ["acme"]`, `realm_access.roles: ["accountant"]`, `aud: "api"`, `iss: http://localhost:8080/realms/invoice`.
- `viewer@globex.example`: `organization: ["globex"]`, roles `["viewer"]`.
- `consultant@demo.example` với scope `openid`: không có claim `organization`; với `organization:*`: `["globex","acme"]`; với `organization:acme`: `["acme"]`.
- Admin API: organization id đúng UUID cố định, membership đủ, secret của `web` = giá trị từ biến.
- `pnpm check`: xanh. `pnpm check:secrets`: no leaks found.

## Phương án đã loại

- Cấu hình bằng UI admin rồi export JSON: file dài, id ngẫu nhiên, khó review và khó giải thích. Chọn JSON viết tay tối thiểu.
- Bật password grant trên client `web` để lấy token bằng curl: làm yếu mô hình confidential + PKCE + BFF (ADR 0006). Chọn client `dev-cli` riêng, chỉ dùng cho dev.
- Cho claim mang cả organization id (mapper `addOrganizationId`): cần định nghĩa lại client scope `organization`, dễ làm mất các scope mặc định. Chọn giữ claim mặc định (alias) và để T1.3 ánh xạ alias → UUID.

## Rủi ro

| Rủi ro | Xuất hiện ở đâu | Bắt bằng gì / còn mở |
| --- | --- | --- |
| User nhiều tenant không có claim `organization` nếu chỉ xin scope `organization` | Token của `consultant@demo.example` | Đã kiểm bằng token thật. Mở: T1.5 phải xin `organization:*`; T1.2 phải từ chối token thiếu claim (Phát sinh) |
| Claim chỉ có alias, `tenant_id` là uuid | T1.2 / T1.3 | UUID cố định trong realm (`realm-invoice.json:16,28`); T1.3 cần bảng `tenants` có `alias` (Phát sinh) |
| Role theo realm, không theo organization | `realm-invoice.json:7` | Chấp nhận cho MVP, ghi cho T1.4 (Phát sinh) |
| Client `dev-cli`, mật khẩu demo và secret mặc định nằm trong repo | `realm-invoice.json:80`, `compose.yaml:52` | Dữ liệu giả, chỉ dev; gitleaks sạch. Mở: gỡ ở T4.7 (Phát sinh) |
| Issuer phụ thuộc host của request | Token `iss` | Mở: T1.2 cấu hình issuer tường minh, T4.7 đặt `KC_HOSTNAME` (Phát sinh) |
| Import dùng `IGNORE_EXISTING`: sửa realm JSON không có tác dụng khi realm đã tồn tại | Log `Strategy: IGNORE_EXISTING` | Muốn áp dụng thay đổi phải `down -v` |

## Khái niệm học được

- **Realm**: không gian người dùng, client và role riêng của Keycloak. Ở đây có đúng một realm `invoice` (`realm-invoice.json:2`), theo ADR 0005.
- **Organization = tenant**: bật ở `realm-invoice.json:6`, khai báo ở dòng 14-36; thành viên của tenant là user được liệt kê trong `members`.
- **Role**: `tenant_admin`, `accountant`, `viewer` ở `realm-invoice.json:7-12`; vào token qua `realm_access.roles`.
- **Client confidential + PKCE**: `web` (dòng 38-68) có secret và `pkce.code.challenge.method: S256`, dùng cho Auth.js ở T1.5.
- **Client bearer-only / audience**: `api` (dòng 70-77) không đăng nhập; token của `web` mang `aud: api` nhờ mapper `oidc-audience-mapper` (dòng 60) để T1.2 kiểm `aud`.
- **Realm-as-code**: file JSON trong git + `--import-realm` (`compose.yaml:47`) → môi trường dựng lại giống hệt, không cấu hình tay.
- **Scope quyết định claim**: claim `organization` phụ thuộc scope xin lúc đăng nhập, không chỉ vào cấu hình mapper.
