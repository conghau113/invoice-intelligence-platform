## Cách tự chạy lại
```bash
pnpm infra:up            # docker compose up -d --wait → chờ tất cả healthy
docker compose ps
docker compose exec postgres psql -U invoice -d invoice -c "CREATE EXTENSION IF NOT EXISTS vector;"
curl -sI http://localhost:8080/admin/     # 302 → /admin/master/console/
pnpm infra:check-arm
pnpm infra:down          # giữ volume;  `docker compose down -v` để xoá dữ liệu
```
Cổng host: Postgres 5433, Redis 6380, Keycloak 8080 (tài khoản admin dev lấy từ biến trong compose.yaml, chỉ bind 127.0.0.1).

## Phương án đã loại
Postgres riêng cho Keycloak: cô lập hơn nhưng thêm ~0,5 GB RAM; ngân sách VM Oracle (ARCHITECTURE §7) chỉ tính một Postgres. Chọn một Postgres, hai DB (`invoice`, `keycloak`).

## Rủi ro
- **Xung đột cổng Windows** (đã gặp): Postgres/Redis native chiếm 5432/6379 → đổi host port 5433/6380 (`compose.yaml:16`, `:34`). Bắt bởi lỗi bind khi `up`. Còn mở: T1.2/T1.3 phải dùng đúng cổng (đã ghi Phát sinh).
- **Healthcheck Keycloak** (`compose.yaml:61-72`): image không có curl, dùng bash `/dev/tcp` tới cổng quản lý 9000. Đã chạy thật → `healthy`. Nếu đổi version Keycloak cần chạy lại.
- **Init script chỉ chạy lần đầu** (`compose.yaml:19`): sửa script mà không `down -v` thì không có tác dụng.
- **Mật khẩu dev mặc định nằm trong compose** (`${VAR:-...}`): chỉ dùng local, bind 127.0.0.1; production (T4.7) phải bắt buộc đặt biến.
- **Dữ liệu thừa:** bảng thử `persist_probe` đã mất khi Hậu xóa volume; DB dev được khởi tạo lại sạch.
- **Từ reviewer — Keycloak dùng chung user chủ DB** (`compose.yaml:53-54`): owner/superuser bỏ qua RLS. Ở dev chấp nhận được; T1.3 không được cho app kết nối bằng user này, T4.7 nên tách role `keycloak`. Đã ghi Phát sinh.
- **Từ reviewer — chưa ghim chặt image** và secret mặc định trong compose: xử lý ở T4.7. `check-arm64.mjs` có thể báo FAIL nhầm với manifest đơn kiến trúc (3 image hiện tại không gặp).
- **Còn mở:** bằng chứng healthy/vector/arm64 do agent chạy; reviewer không chạy docker nên không kiểm lại độc lập.

## Khái niệm học được
- **healthcheck**: `compose.yaml:21` (pg_isready), `:37` (redis-cli ping), `:61` (Keycloak /health/ready). Nghĩa: Docker biết service *sẵn sàng*, không chỉ *đang chạy*.
- **depends_on + service_healthy**: `compose.yaml:58-60`. Keycloak chỉ khởi động khi Postgres healthy; `depends_on` thường chỉ chờ container *start*.
- **Volume đặt tên**: `compose.yaml:18` (`pgdata`), khai báo `:79`. Đã kiểm: `down` xoá container nhưng `invoice-intelligence_pgdata` còn, dữ liệu (42) vẫn đọc được sau `up`. Chỉ `down -v` mới mất.
- **Bind mount** (khác): `compose.yaml:20` ánh xạ thư mục repo vào container (`:ro`).
- **Network riêng**: `compose.yaml:76`, các service gọi nhau bằng tên (`postgres:5432` trong `KC_DB_URL`), không qua cổng host.
- **Cổng bind 127.0.0.1**: `compose.yaml:16`, `:34`, `:57` — không lộ ra mạng LAN.
