## Cách tự chạy lại

```bash
cd apps/ai && uv run pytest -q                 # 94
pnpm --filter api test                          # 259 (cần contracts đã build: pnpm --filter contracts build)
pnpm --filter api test:int                      # 104, cần Docker
pnpm --filter web test                          # 379
pnpm check && pnpm test:scripts
```

Chạy tay với stack thật: `pnpm infra:up`, `pnpm db:migrate`, rồi mỗi terminal một lệnh: `AI_SERVICE_TOKEN=dev-only-ai-service-token pnpm --filter ai dev`, `pnpm dev:api`, `QUEUE_BACKOFF_BASE_MS=200 pnpm dev:worker`, `pnpm --filter web dev`; đăng nhập `accountant@acme.example`, upload XML mẫu (`apps/ai/tests/fixtures/xml_invoices/invoice-00.xml` thêm một comment để đổi hash), mở dòng trong danh sách. Tắt AI rồi upload lại để thấy `failed` + lý do.

Kết quả đã chạy (Playwright tạm, đã xoá): upload xong → thấy tổng tiền trên trang chi tiết sau 8,5s (gồm cả tải danh sách 1.407 dòng và bấm link, ở chế độ dev); AI tắt → `failed` sau ~4,4s (backoff 200ms) với `EXTRACTION_RETRIES_EXHAUSTED` và câu giải thích.

Drill (đều làm test đỏ): bỏ kiểm token ở AI (3 test); 4xx coi là tạm thời (5 test); bỏ `ON CONFLICT` (test hai lượt chạy đồng thời); bỏ ghi `failure_code` (6 test); bỏ validate khi đọc (test dữ liệu hỏng).

## Phương án đã loại

- Đọc lý do `failed` từ `audit_logs.meta.code`: không có index theo `entity_id`, "mới nhất" sai khi nhiều lần failed→queued, danh sách sau này cũng cần. Chọn cột `documents.failure_code`.
- JWT/mTLS giữa các service: quá nặng cho một VM; `API.md` đã ghi token dùng chung.
- Worker gọi API để lưu kết quả (sơ đồ ARCHITECTURE §6.1): worker đã có `TenantDbService` (ADR 0008), ghi thẳng DB, bớt một bước mạng.
- Stream multipart từ đĩa: `fetch` cần `Blob`; đọc ≤10 MB vào RAM là chấp nhận được.

## Sau code-reviewer (2026-11-02)

Không có lỗi mức Cao. Đã sửa:

- **Vừa: 401/403/404 từ AI từng là lỗi vĩnh viễn** (`http-ai-extractor.ts`, nhóm `MISCONFIGURED`). Cấu hình sai (xoay token, deploy lệch) làm mọi document `failed` ngay và trông như lỗi file. Cân nhắc ba phương án: giữ vĩnh viễn; retry rồi `EXTRACTION_RETRIES_EXHAUSTED`; retry rồi mã riêng. Chọn cái thứ ba vì (1) lỗi này do vận hành, không do tài liệu, nên phải được retry; (2) giữ mã riêng để UI nói "không phải lỗi tệp của bạn"; (3) cùng phân loại sẽ dùng cho API key LLM sai ở T3.2 và cho circuit breaker ở T6.7 (nhóm "lỗi sửa được bằng vận hành"). Cái giá: thêm `TransientExtractionError(code)` vào `queue/domain/extraction-job.ts` và một dòng ở `extraction.processor.ts` (mã giữ lại khi hết lượt). Test: spec cho 401/403/404 và int test token sai → 5 lượt → `AI_SERVICE_MISCONFIGURED` → admin retry sau khi sửa → `needs_review`. `SERVICE_UNAUTHORIZED` không còn được lưu; UI thay bằng `AI_SERVICE_MISCONFIGURED`.
- **Thấp: đọc body bị cắt/timeout** nay là lỗi tạm thời (tách `res.text()` khỏi `JSON.parse`; ban đầu dùng `instanceof SyntaxError` nhưng test cho thấy lỗi từ `res.json()` khác realm với jest, nên không tin được).
- **Thấp: `XML_FORBIDDEN_CONSTRUCT`** thiếu bản dịch: đã thêm. Để lần sau không quên, `xml_invoice.py` có `ERROR_CODES` (đăng ký bắt buộc: mã lạ làm `XmlInvoiceError` ném `ValueError`) và pytest khẳng định đúng tập mã, ghi chú trỏ tới danh sách của UI. Đây là chốt chặn, không phải đồng bộ tự động.
- Mục 5, 7, race gọi AI hai lần, `.mcp.json`, `.env.example` của api: ghi vào "Phát sinh" hoặc chờ Hậu (xem TASKS.md).
