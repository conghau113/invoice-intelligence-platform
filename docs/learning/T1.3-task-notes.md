## Cách tự chạy lại

```bash
pnpm infra:up
export DATABASE_OWNER_URL=postgres://invoice:invoice-dev-only@localhost:5433/invoice
export APP_DB_PASSWORD=invoice-app-dev-only
export DATABASE_URL=postgres://invoice_app:invoice-app-dev-only@localhost:5433/invoice
pnpm --filter api db:migrate      # chạy lại lần 2 vẫn sạch (build vào dist-scripts/)

pnpm --filter api test            # unit, không cần DB (49 test)
pnpm --filter api test:int        # cần Postgres thật, 20 test
```

Chạy API: `NODE_ENV=development OIDC_ISSUER_URL=http://localhost:8080/realms/invoice pnpm --filter api start:dev`, sau đó `curl localhost:3001/health/ready` và `/auth/me` với token như ghi chú T1.2. Lưu ý: từ giờ API cần đã chạy `db:migrate` + `db:seed`, nếu không mọi token đều bị 403 "Unknown tenant".

Drill đã chạy trên DB tạm: `ALTER TABLE memberships NO FORCE ROW LEVEL SECURITY` → 1 test đỏ; `ALTER TABLE audit_logs DISABLE ROW LEVEL SECURITY` → 4 test đỏ; cho "app" kết nối bằng owner → 16 test đỏ.

## Phương án đã loại

Khai báo policy bằng `pgPolicy` trong `schema.ts`. Đã grep mã nguồn `drizzle-orm@0.45.4` và `drizzle-kit@0.31.11`: chỉ có `ENABLE ROW LEVEL SECURITY`, không có `FORCE`, mà ADR 0003 bắt buộc FORCE. Một file SQL duy nhất cũng dễ review và dễ "tắt policy" cho bài gỡ lỗi cuối mốc.

## Rủi ro

- **Tra tenant trước khi biết tenant** (`drizzle/0002_resolve_tenant_policy.sql`): bản đầu dùng `SECURITY DEFINER` và **hỏng khi owner không phải superuser** (FORCE RLS áp dụng cả cho owner nên hàm trả NULL cho mọi alias; dev không thấy vì owner là superuser). Code-review phát hiện, mình tái hiện rồi thay bằng hàm thường + policy `tenant_resolve` (chỉ thấy dòng có `alias` = `app.resolve_alias`). Test `works when the table owner is a normal role` đổi owner sang role thường trong một transaction rồi rollback; test đỏ với bản cũ, xanh với bản mới. Phạm vi lộ ra không đổi (biết alias thì biết id). Cần bạn đọc kỹ nhất.
- **Sửa bằng `0002`, không sửa `0001`**: DB dev đã áp `0001`, sửa file đã áp sẽ không chạy lại. Đã thử đường nâng cấp (DB dev) và DB trống.
- **Code-review (10 phát hiện)**: đã sửa #1 (tra tenant), #2 (shutdown hook), #7 (`db:*` ghi vào `dist-scripts/`, trước đó `nest build` xoá `dist/`), #8 (`run` là async), #9 (`isUuid` dùng chung). #3, #4, #5, #6, #10 đã ghi Phát sinh.
- **Giá trị `''` sau transaction**: `current_setting` trả chuỗi rỗng, không phải NULL, trên connection tái dùng. Đã xử lý bằng `NULLIF` (`0001_rls.sql:29`); test dùng pool `max: 1` để ép tái dùng.
- **Interceptor giữ một connection suốt request** (`tenant-transaction.interceptor.ts:20`): request dài có thể cạn pool. Chưa xử lý, đã ghi Phát sinh cho T2.3/T2.9.
- **Test RLS tích hợp chưa chạy trong CI** (CI không có Postgres). Chỉ chạy tay; T1.8 chuyển sang Testcontainers và nối CI (đã ghi Phát sinh). Thiếu cấu hình thì test **fail**, không skip.
- **`users` có policy INSERT mở** (`WITH CHECK (true)`): để tạo user lười ở lần đăng nhập đầu. INSERT ... RETURNING cần SELECT policy nên phải thêm membership trước khi đọc lại user (ghi trong SQL và Phát sinh T1.7).
- **Test "không đổi được schema" chạy được `CREATE TABLE`** nếu ai đó trỏ `DATABASE_URL` vào owner (đã xảy ra trong drill; test catalog bắt được bảng `sneaky` thừa). Chỉ xảy ra khi cấu hình sai.
- **Mật khẩu role app đi qua câu lệnh `ALTER ROLE`**: nếu Postgres bật `log_statement` thì mật khẩu vào log máy chủ. Dev không bật; production (T4.7) cần xem lại.
- **Hook `guard.mjs` chặn heredoc có tên file env** (lỗi đã ghi ở Phát sinh T0.9, gặp lại một lần); đã dùng Write/Edit thay thế.

## Khái niệm học được

- **RLS + FORCE**: `drizzle/0001_rls.sql:48` (`FORCE`), `:50` (policy `tenant_isolation`). Nghĩa: dù là owner, bảng vẫn bị lọc; nhưng superuser vẫn bỏ qua, nên mới cần role app riêng.
- **Role app không phải owner/superuser**: `drizzle/0001_rls.sql:13-18` (tạo role) và test `db.int-spec.ts` ("is not a superuser...").
- **`set_config(..., true)` trong transaction + connection pooling**: `src/db/tenant-db.service.ts:27`. Nghĩa: giá trị chỉ sống đến hết transaction nên connection trả về pool không mang tenant cũ.
- **Defense in depth / fail closed**: policy trả 0 dòng khi thiếu tenant (`0001_rls.sql:29`), GRANT tường minh không có `DEFAULT PRIVILEGES`, `audit_logs` chỉ `SELECT, INSERT` (`:75`).
- **Interceptor chạy sau guard**: `src/db/db.module.ts:35` đăng ký `APP_INTERCEPTOR`; `tenant-transaction.interceptor.ts:20` bỏ qua request không có `req.user` (@Public).
- **Index cho RLS**: `schema.ts` (`memberships_user_id_idx`, `audit_logs_tenant_at_idx`, PK `(tenant_id, user_id)`). Policy là một điều kiện `tenant_id = ...` thêm vào mọi truy vấn, nên cột `tenant_id` phải đứng đầu index; hàm `STABLE` cho phép planner dùng index.
- **Policy bổ sung thay vì đặc quyền**: `0002_resolve_tenant_policy.sql` (policy `tenant_resolve` + `app_resolve_tenant`); chỗ dùng: `modules/auth/infra/pg-tenant-directory.ts`. Nghĩa: FORCE RLS trói cả owner, nên "đường tắt" phải là một policy hẹp chứ không phải quyền owner.
