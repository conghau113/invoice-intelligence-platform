# T0.2 — Ghi chú sau cổng hiểu (apps/web: Next.js + Tailwind + shadcn/ui)

## 1. Luồng chạy từ đầu đến cuối

**Câu hỏi:** Chạy `pnpm --filter web dev` rồi mở `/`: request đi qua những file nào, render ở đâu? `layout.tsx` và `page.tsx` quan hệ thế nào? CSS Tailwind và `Button` shadcn vào trang bằng đường nào? `/api/health` khác `/` ở đâu?

**Trả lời:**
- `pnpm --filter web` chỉ chọn package `web` trong workspace; script `dev` trong `apps/web/package.json` chạy `next dev` (Turbopack), lắng nghe `:3000`.
- `GET /` khớp `src/app/page.tsx` (App Router khớp theo cấu trúc thư mục). `src/app/layout.tsx` bọc ngoài, `page` đi vào `{children}`. `layout` là khung chung (`<html>`, `<body>`, import `globals.css`, font Geist).
- `globals.css` có `@import 'tailwindcss'`. `postcss.config.mjs` khai báo plugin `@tailwindcss/postcss`, plugin này quét mã nguồn, thấy class nào dùng thì chỉ sinh CSS cho class đó. HTML trỏ tới file CSS bằng thẻ `<link>`, trình duyệt tải riêng.
- `Button` (`src/components/ui/button.tsx`) được `page.tsx` import, render ra `<button>` trên server; style đến từ class Tailwind và token (biến CSS) trong `globals.css`.
- `GET /api/health` khớp `src/app/api/health/route.ts`: Route Handler, tên hàm export `GET` là HTTP method. Không có layout, không có React UI, chỉ trả JSON. Cùng server Next, khác nhánh với trang HTML.

**Lưu ý:**
- Một đường dẫn không thể vừa có `page.tsx` vừa có `route.ts`.
- Server Component không có nghĩa là không có JS nào: Next vẫn gửi JS runtime nhỏ. Khác biệt là code của `page.tsx` và `button.tsx` không nằm trong bundle client.
- Turborepo không tham gia lệnh `pnpm --filter web dev`.
- `apps/web/AGENTS.md` do `next dev` tự sinh và tự tạo lại; đã quyết định giữ trong repo.

## 2. Vì sao chọn cách này, phương án khác, đánh đổi

**Câu hỏi:** (a) Vì sao shadcn/ui thay vì MUI hoặc Ant Design? (b) Vì sao `tsconfig.json` của web `extends` `tsconfig.base.json`? (c) Vì sao không dùng `create-next-app` nguyên bản trong monorepo?

**Trả lời:**
- (a) shadcn copy mã nguồn component vào repo (`components/ui`), ta sở hữu và sửa trực tiếp, style bằng Tailwind và token của dự án, chỉ bundle phần dùng. Đổi lại phải tự bảo trì, update thủ công, không có vá lỗi tự động. MUI/Ant: dependency đóng gói, nhiều component có sẵn, nhưng nặng hơn, khó lệch khỏi giao diện mặc định, thêm một hệ styling riêng.
- (b) Một chỗ giữ cờ chặt (`strict`, `noUncheckedIndexedAccess`...) cho cả monorepo; sửa một lần, mọi app theo. App chỉ ghi đè phần môi trường (`module`, `moduleResolution`, `lib`, `jsx`, `plugins`, `paths`, `include`). Copy cờ vào từng app dễ lệch nhau.
- (c) `create-next-app` giả định một repo đơn: tự cài và sinh lockfile, ESLint, `tsconfig` riêng, không biết `tsconfig.base.json` hay workspace. Tự dựng cấu hình để `apps/web` là package `web`, extends base, script khớp các task trong `turbo.json`.

**Lưu ý:**
- shadcn vẫn có dependency: `radix-ui` (hành vi, accessibility), `class-variance-authority`, `cn`, và CLI `shadcn` (vì `globals.css` import `shadcn/tailwind.css`). "Sở hữu mã" chỉ nghĩa là sở hữu lớp style và cấu trúc.
- Gói `cn@0.4.0` là gói của shadcn (MIT, repo `shadcn-ui/cn`), không phải gói `cn` cũ trên npm. Agent từng nhầm nó là gói lạ và tự thêm `clsx` + `tailwind-merge`, sau đó đã gỡ.
- `extends` chỉ kế thừa `compilerOptions`; `include`, `exclude`, `paths` phải khai báo lại ở app.
- Agent đã nói sẽ đối chiếu với output `create-next-app` ở scratchpad nhưng không làm bước đó; chỉ kiểm chứng bằng `build` và `lint` pass.
- `pnpm-workspace.yaml` có `allowBuilds: unrs-resolver: false`: postinstall của gói này chỉ là fallback cho nền tảng không có binary dựng sẵn nên bỏ qua; `sharp` không cần liệt kê vì không bị pnpm chặn.

## 3. Nó hỏng ở đâu, lỗi lộ ra ở tầng nào

**Câu hỏi:** Nếu ai đó dùng `useState` trong `page.tsx` mà không thêm `"use client"`, lỗi lộ ra ở tầng nào đầu tiên, test nào bắt được? Và nếu `GET /api/health` trả 500 thì phát hiện ở đâu?

**Trả lời:**
- `useState` ở Server Component: `pnpm lint` và `pnpm typecheck` đều pass; lỗi lộ ra ở `pnpm build` (hoặc `next dev` khi route được biên dịch), thông điệp đại ý là hook chỉ dùng được trong Client Component, cần `"use client"`. Đó là cổng biên dịch RSC của Next/Turbopack.
- Hiện không có test web nào bắt lỗi này (T0.2 chưa có Vitest, chưa có CI). Từ T0.7: CI chạy `build` nên merge sẽ đỏ.
- `/api/health` 500 là lỗi runtime: lint, typecheck và build đều không bắt được (handler dynamic, không chạy lúc build). Phát hiện bằng test gọi `GET()` (Vitest, T0.7), smoke test `next start` + curl trong CI hoặc `check:full`, hoặc e2e. Docker healthcheck ở T0.6 chỉ cho Postgres/Redis/Keycloak, không phải route Next.

**Lưu ý:**
- Lint không bắt được vì `eslint-plugin-react-hooks` chỉ kiểm tra Rules of Hooks, không biết file ở phía server hay client. Typecheck không bắt được vì `useState` có kiểu hợp lệ; đây là lỗi môi trường chạy, không phải lỗi kiểu.
- Theo spec T0.7, `check:fast` = lint + typecheck + unit, không có build. Lỗi ranh giới server/client có thể lọt local nếu không chạy build.
- Hai loại test khác nhau: test gọi `GET()` chứng minh logic handler; smoke test `next start` + curl chứng minh route được nối đúng vào server.
- Route handler GET mặc định không cache tĩnh từ Next 15: output build ghi `ƒ /api/health` (dynamic). Nhận định "bị cache tĩnh lúc build" của reviewer không đúng với build thực tế.

## 4. Câu hỏi "Cổng hiểu" của task

**Câu hỏi:** Server Component và Client Component khác nhau thế nào? Trang `/` hiện tại là loại nào?

**Trả lời:**
- Server Component chạy trên server (lúc build hoặc lúc có request), logic của nó không vào JS bundle client; trình duyệt chỉ nhận HTML và RSC payload. Làm được: đọc secret, truy cập DB, `async` component, dùng module chỉ chạy Node, giảm JS gửi xuống.
- Client Component được render lần đầu trên server rồi hydrate trên trình duyệt; code của nó có trong bundle client. Làm được: `useState`, `useEffect`, `onClick`, API trình duyệt, tương tác realtime.
- `"use client"` đặt ở đầu file tạo ranh giới: file đó và các module nó import nằm phía client. Server Component import Client Component được (client nhận "khe" có JS). Client Component không import trực tiếp Server Component; phải truyền qua `children` hoặc props.
- Trang `/` (`src/app/page.tsx`) là Server Component vì không có `"use client"`; `Button` cũng chạy trên server vì file import nó là Server Component và nó không dùng hook hay sự kiện.

**Lưu ý:**
- `/` được prerender tĩnh lúc build (ký hiệu `○` trong output build): với trang này, "server" nghĩa là server lúc build, chưa có render theo từng request.
- `button.tsx` là component dùng chung: nó chạy phía nào tùy file import nó. Chỉ cần `"use client"` riêng khi tự dùng hook hay sự kiện.
- Ở M1, những chỗ cần `"use client"` thường là form, ô chọn, bất cứ thứ gì có `onClick`/state. Giữ ranh giới càng thấp trong cây component càng tốt để bundle client nhỏ.
